# วิธีรับชุด: จัดส่ง หรือ รับเองที่ร้าน (v3)

เอกสารต่อจาก [calendar-logic.md](calendar-logic.md) (v2 — ลูกค้าเลือกจำนวนวันเช่า)
เพิ่มตัวเลือกให้ลูกค้ามารับชุดเองที่ร้าน หรือเรียกไรเดอร์มารับแทน เพื่อรองรับกรณี "ต้องการชุดวันนี้"

> **สถานะ:** แก้หน้าเว็บแล้ว · SQL migration ส่งให้รันใน Supabase แยก (ยังไม่อยู่ใน repo)
> ข้อมูลร้าน (ที่อยู่ เวลาเปิด) เป็นค่าสมมติสำหรับโปรเจกต์
>
> **ตัดสินใจระหว่างทำ**
> - วันใส่เร็วสุดคำนวณที่เดียวใน `public.earliest_start_date(method)` ใช้ทั้ง `get_unavailable_start_dates` และ `create_booking`
> - `p_delivery_method` / `p_return_method` ต่อท้าย signature เดิม (default `'ship'`) — ต้อง drop ฟังก์ชันตัวเดิมก่อน
> - ส่งมอบที่ร้านตั้ง `received_at` ด้วย ให้เหมือนลูกค้ากด "ได้รับชุด"
> - ตัวกรอง "ว่างวันที่…" หน้ารวมชุดยังคิดแบบจัดส่ง (ไม่สัญญาวันที่ต้องมาที่ร้าน)
> - ปุ่ม "รับคืนที่ร้าน" ฝั่งแอดมินใช้ได้กับทุกออเดอร์ `active` ที่ลูกค้ายังไม่กรอกเลขพัสดุคืน

## สรุป

| | จัดส่ง (EMS) — เดิม | รับเองที่ร้าน — ใหม่ |
|---|---|---|
| ใช้กับ | ลูกค้าทั่วไป | ลูกค้ามารับเอง **หรือลูกค้าเรียกไรเดอร์มารับ** |
| จองได้เร็วสุด | วันนี้ + `greatest(min_lead_days, buffer_days_before)` | **วันนี้** ถ้าจองก่อนเวลาตัดรอบ ไม่งั้นพรุ่งนี้ |
| ลูกค้าได้ชุด | วันใส่ − `buffer_days_before` | **วันใส่** (มารับที่ร้านในเวลาเปิด) |
| ช่วงล็อกชุด | `[วันใส่ − buffer_before, วันคืน + buffer_after]` | `[วันใส่, วันคืน + buffer_after]` |
| ค่าส่ง | `shipping_flat_rate` | 0 |
| ที่อยู่จัดส่ง | ต้องกรอก | ไม่ต้อง (กรอกแค่ชื่อและเบอร์ผู้ติดต่อ) |
| ร้านทำอะไร | แพ็ก → ส่ง → กรอกเลขพัสดุ | เตรียมชุด → ส่งมอบที่ร้าน → บันทึกผู้รับ |
| การคืนชุด | ส่งพัสดุกลับ หรือนำมาคืนที่ร้าน | ส่งพัสดุกลับ หรือนำมาคืนที่ร้าน |

### หลักการที่ทำให้ไม่ซับซ้อน

1. **ไรเดอร์ไม่ใช่วิธีที่สาม** — ลูกค้าเป็นคนเรียกและจ่ายค่าไรเดอร์เอง สำหรับร้านคือ "มีคนมารับที่ร้าน" ระบบไม่ต้องคิดค่าไรเดอร์ ไม่ต้องรู้ระยะทาง ไม่ต้องเชื่อมแอปไรเดอร์
2. **วิธีรับชุดเป็นของทั้งออเดอร์และทั้งตะกร้า** — ตะกร้าหนึ่งใช้วิธีเดียว ค่าส่งคิดต่อออเดอร์เหมือนเดิม
3. **วิธีคืนไม่ผูกกับวิธีรับ** — `buffer_days_after` (ตรวจ/ซัก) ใช้เท่าเดิมทุกกรณี
4. **ไม่เพิ่มสถานะออเดอร์** — รับเองที่ร้านกด "ส่งมอบแล้ว" แล้วไป `active` เลย ไม่ผ่าน `shipped`

### ไม่ทำในรอบนี้

- ร้านเรียกไรเดอร์ไปส่งให้ลูกค้า (ต้องคิดค่าส่งตามระยะทาง)
- ให้ลูกค้ามารับก่อนวันใส่ (รับได้เฉพาะวันใส่ ถ้าอยากได้ก่อนให้เลือกวันใส่เร็วขึ้นแล้วเช่าเพิ่มวัน)
- ตะกร้าเดียวหลายวิธีรับ

## 1. ค่าตั้งใหม่ (`app_settings`)

| key | ค่าสมมติ | ความหมาย |
|---|---|---|
| `pickup_lead_days` | 0 | จองล่วงหน้าขั้นต่ำสำหรับรับเอง (0 = รับวันนี้ได้) |
| `pickup_cutoff_hour` | 15 | จองหลัง 15:00 (เวลาไทย) วันใส่เร็วสุดเลื่อนไป 1 วัน — ใช้เมื่อ `pickup_lead_days = 0` |
| `pickup_location` | ดูด้านล่าง | ข้อมูลร้านที่แสดงให้ลูกค้า (jsonb) |

```json
{
  "name": "CosMate Studio (สมมติ)",
  "address": "123/4 ถนนตัวอย่าง ตำบลสมมติ อำเภอเมือง จังหวัดนครปฐม 73000",
  "hours": "ทุกวัน 10:00–19:00",
  "phone": "080-000-0000",
  "map_url": ""
}
```

- ค่าตัวเลขอ่านผ่าน `setting_int()` เหมือนเดิม `pickup_location` อ่านตรงจาก `app_settings`
- หน้าเว็บได้ค่าทั้งหมดจาก `get_rental_day_settings()` ตัวเดิม (เพิ่ม key ในผลลัพธ์)
- ถ้า `pickup_location` ว่าง หน้าเว็บ**ซ่อนตัวเลือกรับเองที่ร้าน** (ปิดฟีเจอร์ได้โดยไม่แก้โค้ด)

## 2. วันที่จองได้และช่วงล็อก

### วันใส่เร็วสุด

```
จัดส่ง:       today + greatest(min_lead_days, buffer_days_before)

รับเองที่ร้าน: today + pickup_lead_days
              + (1 ถ้า pickup_lead_days = 0 และ ตอนนี้ ≥ pickup_cutoff_hour:00)
```

`today` และ "ตอนนี้" ใช้เวลา `Asia/Bangkok` เหมือนเดิม

### ช่วงล็อก

```
end_date = start_date + rental_days − 1

จัดส่ง:       blocked_during = [start_date − buffer_days_before , end_date + buffer_days_after]
รับเองที่ร้าน: blocked_during = [start_date ,                      end_date + buffer_days_after]
```

`blocked_during` บันทึกตอนจอง จึงไม่ต้องรู้วิธีรับย้อนหลัง — exclusion constraint และ `get_occupied_dates` ใช้ได้เหมือนเดิม

### ตัวอย่าง

ค่าปัจจุบัน: `buffer_before = 1`, `buffer_after = 2`, `min_lead_days = 3`, วันนี้ 25 ต.ค. เวลา 11:00, เช่า 1 วัน

| วิธีรับ | วันใส่เร็วสุด | ช่วงล็อก ถ้าใส่วันเร็วสุด |
|---|---|---|
| จัดส่ง | 28 ต.ค. | 27–30 ต.ค. |
| รับเองที่ร้าน | **25 ต.ค.** | 25–27 ต.ค. |
| รับเองที่ร้าน (จองตอน 16:00) | 26 ต.ค. | 26–28 ต.ค. |

### วันที่เริ่มเช่าไม่ได้ขึ้นกับวิธีรับ

ชุดมีการจองเดิมล็อก 9–13 ลูกค้าใหม่เช่า 1 วัน

| วิธีรับ | ช่วงล็อกของลูกค้าใหม่ที่ใส่วัน D | วันที่เริ่มไม่ได้ |
|---|---|---|
| จัดส่ง (`b = 1`, `a = 2`) | `[D−1, D+2]` | 7–14 |
| รับเองที่ร้าน (`a = 2`) | `[D, D+2]` | 7–13 |

รับเองที่ร้านว่างกว่าฝั่งหลังการจองเดิม 1 วัน (วันที่ 14) เพราะไม่ต้องกันวันขนส่งไว้ก่อนวันใส่

## 3. ฐานข้อมูล

### 3.1 คอลัมน์ใหม่ใน `orders`

```sql
alter table public.orders
  add column delivery_method text not null default 'ship'
    check (delivery_method in ('ship', 'pickup')),
  add column handover_to     text,         -- ชื่อผู้มารับ (ลูกค้า หรือ ไรเดอร์ + ทะเบียน)
  add column handed_over_at  timestamptz,
  add column return_method   text
    check (return_method in ('ship', 'walk_in'));  -- บันทึกตอนร้านรับคืน
```

- ออเดอร์เดิมทั้งหมดได้ `delivery_method = 'ship'` จาก default
- ⚠️ **ต้องตรวจ:** `ship_address`, `ship_province`, `ship_postal_code` (และอาจรวม `ship_subdistrict`, `ship_district`) ตอนนี้น่าจะเป็น `not null` — ต้อง `drop not null` แล้วเพิ่ม check แทน

```sql
alter table public.orders
  alter column ship_address     drop not null,
  alter column ship_province    drop not null,
  alter column ship_postal_code drop not null,
  add constraint orders_ship_needs_address check (
    delivery_method <> 'ship'
    or (ship_address is not null and ship_province is not null and ship_postal_code is not null)
  );
```

`ship_name` / `ship_phone` ยังบังคับ (ใช้เป็นผู้ติดต่อของออเดอร์รับเองด้วย)

### 3.2 `get_unavailable_start_dates` — เพิ่มพารามิเตอร์วิธีรับ

```
get_unavailable_start_dates(p_variant_id, p_days_ahead, p_rental_days, p_delivery_method text default 'ship')
```

- ⚠️ ต้อง `drop function public.get_unavailable_start_dates(uuid, integer, integer)` ก่อนสร้างใหม่ (กัน overload)
- `p_delivery_method` นอก `('ship','pickup')` → `raise exception 'INVALID_DELIVERY_METHOD'`
- ใน `cfg`:
  - `b` = `buffer_days_before` ถ้า ship / `0` ถ้า pickup
  - `earliest` = สูตรวันใส่เร็วสุดในข้อ 2
- เงื่อนไข: `(today + g) < earliest` หรือวันคืนเลย 120 วัน หรือไม่มีชุดว่างตลอด `[D − b, D + rental_days − 1 + a]`

### 3.3 `get_occupied_dates` — ไม่เปลี่ยน

อ่านจาก `blocked_during` ที่บันทึกไว้ ซึ่งสะท้อนวิธีรับของการจองเดิมอยู่แล้ว

### 3.4 `create_booking` — เพิ่มพารามิเตอร์วิธีรับ

```
create_booking(p_items, p_delivery_method text default 'ship', p_ship_name, p_ship_phone,
               p_ship_address, ..., p_note)
```

- ⚠️ signature เปลี่ยน → `drop function` ตัวเดิมก่อน และ GRANT ใหม่
  (หรือวาง `p_delivery_method` ไว้ท้ายสุดหลัง `p_note` ให้ลำดับเดิมไม่ขยับ — **แนะนำแบบนี้** เพราะเรียกด้วยชื่อพารามิเตอร์อยู่แล้ว)
- `p_delivery_method` นอก `('ship','pickup')` → `INVALID_DELIVERY_METHOD`
- ship: ต้องมี address/province/postal_code ไม่งั้น `INVALID_ADDRESS`
- `v_before` = `buffer_days_before` ถ้า ship / `0` ถ้า pickup → ใช้ทั้งตรวจ `START_DATE_TOO_SOON` และสร้าง `blocked_during`
- วันใส่เร็วสุดตามสูตรข้อ 2 (pickup ใช้ `pickup_lead_days` + cutoff)
- `v_shipping` = `shipping_flat_rate` ถ้า ship / `0` ถ้า pickup
- insert `orders.delivery_method`
- ส่วนอื่น (ราคา วันเพิ่ม มัดจำ ไล่ชุด) เหมือน v2

### 3.5 `admin_handover_order` — ฟังก์ชันใหม่ (แทน `admin_ship_order` สำหรับรับเอง)

```
admin_handover_order(p_order_id uuid, p_handover_to text, p_checklist jsonb, p_image_paths text[])
```

- ต้องเป็นแอดมิน, ออเดอร์ต้อง `delivery_method = 'pickup'` และ `status = 'paid'` → ไม่งั้น `INVALID_TRANSITION`
- `p_handover_to` ว่าง → `HANDOVER_TO_REQUIRED`
- ต้องมีรูปอย่างน้อย 1 รูป และเช็กลิสต์ครบ (กติกาเดียวกับ `admin_ship_order`)
- บันทึกหลักฐานเป็น stage `packing` เหมือนเดิม → ฝั่งรับคืนเทียบรูปได้เหมือนกัน
- `paid → active`, ตั้ง `handover_to`, `handed_over_at = now()`, เขียนประวัติสถานะ (reason: "ส่งมอบที่ร้าน · <ผู้รับ>")
- ⚠️ ต้องอ่าน `admin_ship_order` ตัวจริงก่อนเขียน เพื่อใช้ตาราง evidence/history ให้ตรง

### 3.6 การรับคืน — รองรับลูกค้านำมาคืนที่ร้าน

ตอนนี้ร้านยืนยันรับคืนไม่ได้ถ้าลูกค้ายังไม่กรอกเลขพัสดุ (`RETURN_TRACKING_REQUIRED`)

- ฟังก์ชันรับคืน (ที่ `receiveAndInspect` เรียก) เพิ่มพารามิเตอร์ `p_return_method text default 'ship'`
- `walk_in` → ไม่ต้องมีเลขพัสดุคืน, บันทึก `orders.return_method = 'walk_in'`
- ใช้ได้กับ**ทุกออเดอร์** (ลูกค้าจัดส่งก็นำมาคืนที่ร้านได้)
- ⚠️ ต้องอ่าน SQL ฟังก์ชันรับคืนตัวจริงก่อนแก้

### รหัส error ใหม่

| รหัส | ความหมาย | ข้อความถึงผู้ใช้ |
|---|---|---|
| `INVALID_DELIVERY_METHOD` | วิธีรับไม่ถูกต้อง | วิธีรับชุดไม่ถูกต้อง กรุณาเลือกใหม่ |
| `INVALID_ADDRESS` | จัดส่งแต่ไม่มีที่อยู่ | กรุณากรอกที่อยู่จัดส่งให้ครบ |
| `HANDOVER_TO_REQUIRED` | แอดมินไม่ได้กรอกผู้รับ | กรอกชื่อผู้มารับชุดก่อนยืนยัน |

`START_DATE_TOO_SOON` ใช้ข้อความเดิม แต่ถ้าเป็น pickup ให้หน้าเว็บเสริมว่า "เลยเวลาตัดรอบรับวันนี้ (15:00) แล้ว"

## 4. ฝั่งลูกค้า

### 4.1 หน้าชุด

ลำดับขั้น: **1. ไซส์ → 2. เช่ากี่วัน → 3. วิธีรับชุด → 4. วันที่จะใส่**
(วิธีรับต้องมาก่อนปฏิทิน เพราะวันที่ว่างขึ้นกับวิธีรับ)

ตัวเลือกวิธีรับเป็นการ์ดสองใบ ค่าเริ่มต้น "จัดส่ง":

```
( ) จัดส่งถึงบ้าน (EMS)                 ( ) รับเองที่ร้าน
    ค่าส่ง ฿100                             ไม่มีค่าส่ง
    ได้รับชุด 1 วันก่อนวันใส่                รับได้วันใส่ · จองก่อน 15:00 รับวันนี้ได้
    จองล่วงหน้าอย่างน้อย 3 วัน              ให้ไรเดอร์มารับแทนได้
```

- เปลี่ยนวิธีรับ → โหลดวันที่เริ่มไม่ได้ใหม่ (cache ตาม `(variant, rental_days, delivery_method)`) และใช้กติกา "วันที่เลือกใช้ไม่ได้ → แจ้งให้เลือกใหม่" แบบเดียวกับเปลี่ยนจำนวนวัน
- ไทม์ไลน์: รับเอง แสดง "รับชุดที่ร้าน = วันใส่" แทน "ได้รับชุด"
- สรุปยอด: ค่าส่ง ฿0
- ถ้าตะกร้ามีของอยู่แล้วและวิธีรับไม่ตรง → กด "เพิ่มลงตะกร้า" แล้วถาม
  "ตะกร้าของคุณเป็นแบบจัดส่ง เปลี่ยนทั้งตะกร้าเป็นรับเองที่ร้านไหม?" (ยืนยัน = เปลี่ยนทั้งตะกร้า / ยกเลิก = ไม่เพิ่ม)

### 4.2 ตะกร้า

- วิธีรับเก็บ**ระดับตะกร้า** (ไม่ใช่ต่อรายการ) ใน localStorage แยกจากรายการ
- แสดงตัวเลือกวิธีรับด้านบนสรุปยอด เปลี่ยนได้ → ตรวจทุกรายการใหม่ (รายการที่วันไม่ว่างสำหรับวิธีใหม่ขึ้นเตือนเหมือนเดิม)
- ลิงก์ไปหน้าชำระเงินแนบ `delivery=pickup|ship`

### 4.3 หน้าชำระเงิน

| | จัดส่ง | รับเองที่ร้าน |
|---|---|---|
| ส่วนที่อยู่ | ฟอร์มที่อยู่ (เดิม) | การ์ดข้อมูลร้าน (ชื่อ ที่อยู่ เวลาเปิด เบอร์ ลิงก์แผนที่) + ช่องชื่อ/เบอร์ผู้ติดต่อ |
| การจัดส่ง | "ไปรษณีย์ไทย (EMS)" | "รับเองที่ร้าน" |
| ค่าส่ง | `shipping_flat_rate` | ฿0 |
| หมายเหตุถึงร้าน | ตัวอย่างเดิม | placeholder: "ถ้าให้ไรเดอร์มารับ แจ้งชื่อไรเดอร์หรือเวลาที่จะมาถึง" |

### 4.4 หน้าออเดอร์

รับเองที่ร้าน สถานะ `paid` แสดงกล่องคำแนะนำ:


## 5. ฝั่งแอดมิน

### 5.1 คิวงาน

- แท็บ "แพ็กและส่งออก" รวมทั้งสองแบบ มีป้าย **"รับที่ร้าน"** ที่ออเดอร์รับเอง
- กำหนดเสร็จ: จัดส่ง = `วันใส่ − buffer_before − 1` (เดิม) / รับเอง = **วันใส่** (เตรียมชุดให้พร้อมก่อนเปิดร้าน)
- แดชบอร์ด "งานวันนี้": ออเดอร์รับเองที่วันใส่ = วันนี้ แสดง "ลูกค้ามารับวันนี้"

### 5.2 แผงออเดอร์รับเอง (แทน `PackForm`)

ใช้โครงเดียวกับ `PackForm`:

1. หยิบชุดจากชั้น (เดิม)
2. เช็กลิสต์ของในกล่อง (เดิม)
3. รูปตอนส่งมอบ (เดิม — ถ่ายจากกล้องได้)
4. **ผู้มารับ** (แทนเลขพัสดุ) — ช่องข้อความ เช่น "คุณมิว (ลูกค้า)" หรือ "ไรเดอร์ Grab · กข 1234"

ปุ่ม "ยืนยันส่งมอบ · ไปถัดไป" → `admin_handover_order`
การ์ดที่อยู่ด้านบนเปลี่ยนเป็น "ผู้ติดต่อ: ชื่อ · เบอร์ · หมายเหตุจากลูกค้า"

### 5.3 แผงรับคืน

เพิ่มตัวเลือกเมื่อลูกค้ายังไม่กรอกเลขพัสดุคืน: **"☐ ลูกค้านำมาคืนที่ร้าน"** → ยืนยันผลตรวจได้โดยไม่ต้องมีเลขพัสดุ

### 5.4 กระดานคิวชุดและอัตราการจอง

`lockRange()` ต้องรู้วิธีรับ: รับเอง `from = startDate` (ไม่ลบ buffer ก่อน)
(หรือดีกว่า: ให้ `fetchOrders` ดึง `blocked_during` มาใช้ตรง ๆ ไม่ต้องคำนวณซ้ำ)

## 6. ลำดับการทำงาน (รับเองที่ร้าน)

```
ลูกค้าเลือกไซส์ → จำนวนวัน → "รับเองที่ร้าน" → วันใส่ (วันนี้ได้ถ้าก่อน 15:00)
  └─ create_booking(p_delivery_method = 'pickup')
       └─ blocked_during = [วันใส่, วันคืน + buffer_after] · ค่าส่ง 0
ลูกค้าจ่ายเงิน → ตรวจสลิป → paid
ร้านเตรียมชุด → ลูกค้า/ไรเดอร์มาถึง → แสดงเลขออเดอร์
  └─ admin_handover_order(ผู้รับ, เช็กลิสต์, รูป) → active
ลูกค้าคืนชุด (พัสดุ หรือ นำมาที่ร้าน) ภายในวันคืน
  └─ รับคืนและตรวจ (เดิม) · walk_in ไม่ต้องมีเลขพัสดุ → completed
```

## 7. ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| คนอื่นแอบอ้างมารับชุด | ต้องแสดงเลขออเดอร์ + ชื่อผู้จอง · แอดมินบันทึกผู้รับและถ่ายรูปตอนส่งมอบ |
| จองวันนี้แต่สลิปตรวจช้า ลูกค้ามาถึงแล้วยังไม่ `paid` | ตัดรอบ 15:00 · ถ้าโหมดตรวจสลิปเป็น manual แอดมินต้องดูคิว "ตรวจยอด" ก่อน |
| ลูกค้าจองรับวันนี้แต่ไม่มา | ไม่ต้องทำอะไรพิเศษ — วันคืน/ค่าปรับคืนช้า/สงสัยไม่คืน ใช้กติกาเดิมนับจากวันคืน · แอดมินโทรตามได้จากเบอร์ผู้ติดต่อ |
| แจ้งปัญหาหลังได้รับชุด (`receipt_issue_hours`) | รับเองตรวจชุดต่อหน้าพนักงานได้อยู่แล้ว · ยังเปิดให้แจ้งได้ภายใน 24 ชม. นับจาก `handed_over_at` |

## 8. กรณีทดสอบ

ค่าตั้ง: `buffer_before = 1`, `buffer_after = 2`, `min_lead_days = 3`, `pickup_lead_days = 0`, `pickup_cutoff_hour = 15`, ไซส์มีชุด 1 ตัว

| # | กรณี | คาดหวัง |
|---|---|---|
| 1 | รับเอง จองตอน 11:00 ใส่วันนี้ 1 วัน | จองได้ · `blocked_during` = [วันนี้, วันนี้+2] · ค่าส่ง 0 |
| 2 | รับเอง จองตอน 16:00 ใส่วันนี้ | `START_DATE_TOO_SOON` · ปฏิทินขีดฆ่าวันนี้ |
| 3 | จัดส่ง ใส่วันนี้+2 | `START_DATE_TOO_SOON` (ต้อง +3) |
| 4 | การจองเดิมล็อก 9–13 · รับเอง 1 วัน | เริ่มไม่ได้ 7–13 (14 จองได้) |
| 5 | การจองเดิมล็อก 9–13 · จัดส่ง 1 วัน | เริ่มไม่ได้ 7–14 |
| 6 | จัดส่ง แต่ไม่ส่งที่อยู่ | `INVALID_ADDRESS` |
| 7 | รับเอง ไม่ส่งที่อยู่ | จองได้ · `ship_address` = null |
| 8 | `p_delivery_method = 'rider'` | `INVALID_DELIVERY_METHOD` |
| 9 | ตะกร้าแบบจัดส่ง กดเพิ่มชุดแบบรับเอง → ยืนยัน | ทั้งตะกร้าเป็นรับเอง · รายการที่วันไม่ว่างขึ้นเตือน |
| 10 | แอดมินส่งมอบโดยไม่กรอกผู้รับ | `HANDOVER_TO_REQUIRED` |
| 11 | แอดมินกดส่งมอบออเดอร์แบบจัดส่ง | `INVALID_TRANSITION` |
| 12 | ส่งมอบสำเร็จ | `paid → active` · `handover_to`, `handed_over_at` มีค่า · มีรูปตอนแพ็ก |
| 13 | ลูกค้านำมาคืนที่ร้าน ไม่มีเลขพัสดุ · แอดมินติ๊ก "นำมาคืนที่ร้าน" | ตรวจรับคืนได้ · `return_method = 'walk_in'` |
| 14 | ออเดอร์เดิมก่อน migration | `delivery_method = 'ship'` · ทุกอย่างทำงานเหมือนเดิม |
| 15 | ลบ `pickup_location` ใน `app_settings` | หน้าเว็บไม่แสดงตัวเลือกรับเองที่ร้าน |

## 9. ก่อนลงมือต้องดู SQL ตัวจริงเพิ่ม

1. นิยามคอลัมน์ `ship_*` ของ `orders` (ตัวไหน `not null`)
2. `admin_ship_order` — ใช้เป็นแม่แบบของ `admin_handover_order`
3. ฟังก์ชันรับคืนที่ `receiveAndInspect()` เรียก — เพิ่ม `walk_in`
4. `confirm_received` (ลูกค้ากดได้รับ / แจ้งปัญหา) และงานตั้งเวลาที่เปลี่ยน `shipped → active` อัตโนมัติ — ให้รองรับออเดอร์ที่ไม่มี `shipped`
5. `submit_return_tracking` — ไม่ต้องแก้ แต่ดูว่ากันสถานะอะไรไว้บ้าง

```sql
select column_name, is_nullable from information_schema.columns
 where table_schema = 'public' and table_name = 'orders' and column_name like 'ship\_%';

select p.proname, pg_get_functiondef(p.oid)
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and p.proname in ('admin_ship_order', 'admin_receive_and_inspect', 'confirm_received', 'submit_return_tracking');

-- งานตั้งเวลา (ถ้าใช้ pg_cron)
select jobname, schedule, command from cron.job;
```
