## 1. ภาพรวม

- **ค่าเช่า** คิดจากต้นทุนชุด และลดลงอัตโนมัติตามช่วงอายุการใช้งานของชุด
  - ชุดใหม่: ราคาสูงกว่าปกติ จนกว่าจะคืนทุน
  - ชุดคืนทุนแล้ว: ราคาปกติ
  - ชุดเก่า (ตัวเลือกเสริม): ราคาลดลงอีกเมื่อถูกเช่าครบจำนวนรอบที่กำหนด
- **ค่ามัดจำ** ใช้ตารางเดิมของร้าน โดยดูจากค่าเช่า ณ ตอนจอง
- **ป้องกันกรณีไม่คืนชุด** ด้วยการยืนยันตัวตน (สำเนาบัตรประชาชน) ร่วมกับมัดจำ

## 3. ช่วงราคาค่าเช่า

ทุกราคาปัดขึ้นเป็นหลัก 50 บาท และค่าเช่าขั้นต่ำคือ 250 บาท

| ช่วง | สูตร | เงื่อนไขเข้าช่วง |
|---|---|---|
| ชุดใหม่ | 50% ของต้นทุน | ค่าเช่าสะสม < ต้นทุน |
| ราคาปกติ | 35% ของต้นทุน | ค่าเช่าสะสม ≥ ต้นทุน |
| ชุดเก่า *(เปิด/ปิดได้)* | 25% ของต้นทุน | เช่าคืนสำเร็จครบ 10 รอบ |

ราคาชุดใหม่ = 50% ของต้นทุน ทำให้ทุกชุด **คืนทุนภายใน 2 รอบ**

### ตัวอย่างราคา

| ต้นทุน | ชุดใหม่ (มัดจำ) | ราคาปกติ (มัดจำ) | ชุดเก่า (มัดจำ) |
|---|---|---|---|
| 600 | 300 (150) | 250 (150) | 250 (150) |
| 1,000 | 500 (150) | 350 (150) | 250 (150) |
| 1,200 | 600 (250) | 450 (150) | 300 (150) |
| 1,500 | 750 (250) | 550 (250) | 400 (150) |
| 1,800 | 900 (250) | 650 (250) | 450 (150) |
| 2,000 | 1,000 (250) | 700 (250) | 500 (150) |
| 2,500 | 1,250 (400) | 900 (250) | 650 (250) |

### ความเสี่ยงกรณีลูกค้าไม่คืนชุดในรอบแรก

| ต้นทุน | ร้านได้ (ค่าเช่า + มัดจำ) | ส่วนที่ขาด |
|---|---|---|
| 600 | 450 | 150 |
| 1,200 | 850 | 350 |
| 1,800 | 1,150 | 650 |
| 2,500 | 1,650 | 850 |

ส่วนที่ขาดนี้ร้านรับความเสี่ยงไว้ และป้องกันด้วยการยืนยันตัวตนในข้อ 6

## 4. ระบบช่วยแอดมินตั้งราคา

### 4.1 ตอนเพิ่มชุดใหม่

แอดมินกรอก **ต้นทุนชุด** อย่างเดียว ระบบแสดงพรีวิว:

```
ต้นทุน: 1,800 บาท

ราคาชุดใหม่      900 บาท   มัดจำ 250   (รอบที่ 1–2)
ราคาปกติ         650 บาท   มัดจำ 250   (ตั้งแต่รอบที่ 3)
ราคาชุดเก่า      450 บาท   มัดจำ 150   (ตั้งแต่รอบที่ 11)

คาดว่าจะคืนทุนหลังรอบที่ 2
ถ้าลูกค้าไม่คืนชุดในรอบแรก: ร้านได้ 1,150 / ขาด 650 บาท
```

### 4.2 แอดมินแก้ราคาเอง

- แอดมินแก้ราคาชุดใหม่หรือราคาปกติได้
- ระบบคำนวณใหม่ทันทีว่าจะคืนทุนในกี่รอบ
- แจ้งเตือนเมื่อ:
  - ราคาชุดใหม่ต่ำกว่า 40% ของต้นทุน → "ชุดนี้จะคืนทุนช้าลงเป็น X รอบ"
  - ราคาต่ำกว่า 250 บาท
  - ต้นทุนอยู่นอกช่วง 600–2,500 บาท → ให้แอดมินกำหนดราคาเอง

### 4.3 ล็อกราคา

แอดมินเลือก "ล็อกราคา" ได้ เพื่อไม่ให้ระบบปรับราคาอัตโนมัติ (เช่น ชุดที่เป็นที่ต้องการสูง)

## 5. Logic ในระบบ

### 5.1 ข้อมูลที่ต้องเก็บ

**ตาราง `deposit_tiers`**

| field | ความหมาย |
|---|---|
| `rent_min`, `rent_max` | ช่วงค่าเช่า |
| `deposit` | ค่ามัดจำ |

**ตาราง `dresses`**

| field | ความหมาย |
|---|---|
| `cost_price` | ต้นทุนชุด |
| `price_new` | ราคาชุดใหม่ |
| `price_normal` | ราคาปกติ |
| `price_old` | ราคาชุดเก่า |
| `price_phase` | `new` / `normal` / `old` |
| `price_locked` | true = ไม่ปรับราคาอัตโนมัติ |
| `completed_rentals` | จำนวนครั้งที่คืนสำเร็จ |
| `total_rental_income` | ค่าเช่าสะสมจากรอบที่คืนสำเร็จ |

**ตาราง `bookings`**

| field | ความหมาย |
|---|---|
| `rental_price_snapshot` | ค่าเช่า ณ ตอนจอง |
| `deposit_snapshot` | มัดจำ ณ ตอนจอง |
| `status` | `booked` / `picked_up` / `returned` / `cancelled` / `not_returned` |

**ตาราง `customers`**

| field | ความหมาย |
|---|---|
| `id_status` | `none` / `pending` / `verified` / `rejected` |
| `id_card_file` | รูปบัตรประชาชน (ที่ลูกค้าเขียนกำกับแล้ว) |
| `id_verified_at` | วันที่แอดมินยืนยัน |
| `last_rental_at` | วันที่เช่าล่าสุด ใช้คำนวณการลบไฟล์อัตโนมัติ |
| `is_blacklisted` | ลูกค้าเคยไม่คืนชุด |

### 5.2 คำนวณราคาตอนเพิ่มชุด

```
function roundUp50(x):
    return ceil(x / 50) * 50

function calcPrices(cost):
    price_new    = max(250, roundUp50(cost * 0.50))
    price_normal = max(250, roundUp50(cost * 0.35))
    price_old    = max(250, roundUp50(cost * 0.25))
    return price_new, price_normal, price_old
```

### 5.3 ราคาปัจจุบันและมัดจำ

```
function currentPrice(dress):
    switch dress.price_phase:
        case "new":    return dress.price_new
        case "normal": return dress.price_normal
        case "old":    return dress.price_old

function lookupDeposit(rental_price):
    tier = deposit_tiers where rent_min <= rental_price <= rent_max
    return tier.deposit
```

### 5.4 ตอนจอง

```
on create booking:
    if customer.is_blacklisted: reject
    if customer.id_status != "verified":
        ให้ลูกค้าส่งรูปบัตร → id_status = "pending"
        แอดมินต้องยืนยันก่อนวันรับชุด
    booking.rental_price_snapshot = currentPrice(dress)
    booking.deposit_snapshot      = lookupDeposit(booking.rental_price_snapshot)
```

ราคาและมัดจำถูกล็อกไว้กับใบจอง ไม่เปลี่ยนตามการปรับราคาภายหลัง

### 5.5 ปรับราคาอัตโนมัติเมื่อคืนชุด

```
on booking status → returned:
    dress.completed_rentals   += 1
    dress.total_rental_income += booking.rental_price_snapshot
    customer.last_rental_at    = today

    if dress.price_locked: return

    if OLD_PHASE_ENABLED and dress.completed_rentals >= 10:
        dress.price_phase = "old"
    elif dress.total_rental_income >= dress.cost_price:
        dress.price_phase = "normal"
    else:
        dress.price_phase = "new"
```

### 5.6 เมื่อลูกค้าไม่คืนชุด

```
on booking status → not_returned:
    ยึดมัดจำ
    customer.is_blacklisted = true
    dress.status = "lost"
    (ไม่นับรอบ และไม่บวกค่าเช่าสะสม)
```

## 6. การยืนยันตัวตน (สำเนาบัตรประชาชน)

### 6.1 ขั้นตอน

- ยืนยัน **ครั้งเดียวตอนเช่าครั้งแรก** แล้วเก็บไว้กับบัญชีลูกค้า ครั้งต่อไปจองได้เลย
- ลูกค้าอัปโหลดรูปบัตรประชาชน โดยเขียนกำกับว่า "ใช้สำหรับเช่าชุดร้าน ... เท่านั้น" พร้อมวันที่
- แอดมินตรวจรูปแล้วกด อนุมัติ (`verified`) หรือ ไม่อนุมัติ (`rejected`) ก่อนวันรับชุด
- ระบบเก็บแค่รูปบัตร ไม่บันทึกเลขบัตรลงฐานข้อมูล

```
none → (ลูกค้าส่งรูป) → pending → (แอดมินตรวจ) → verified
                                              ↘ rejected → (ส่งรูปใหม่) → pending
```

### 6.2 การเก็บและลบข้อมูล (PDPA)

ข้อมูลบัตรประชาชนเป็นข้อมูลส่วนบุคคลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล จึงควร:

- แจ้งวัตถุประสงค์และขอความยินยอมตอนลูกค้าส่งรูป
- จำกัดสิทธิ์ให้เฉพาะแอดมินเปิดดูได้
- เก็บไว้ตราบที่ลูกค้ายังใช้งาน และลบไฟล์อัตโนมัติเมื่อ
  - ไม่มีการเช่าเกิน 1 ปี (นับจาก `last_rental_at`)
  - ลูกค้าขอลบ หรือลบบัญชี
- ยกเว้นลูกค้าที่ไม่คืนชุดหรือมีข้อพิพาท ให้เก็บต่อจนกว่าเรื่องจะจบ

เมื่อไฟล์ถูกลบ ระบบตั้ง `id_status` กลับเป็น `none` ลูกค้าต้องส่งรูปใหม่ในการเช่าครั้งถัดไป

```
daily job:
    for customer where id_status == "verified"
                   and last_rental_at < today − 1 year
                   and not is_blacklisted:
        delete customer.id_card_file
        customer.id_status = "none"
```

## การลงระบบจริง (CosMate)

ตัดสินใจกับเจ้าของร้าน 29 ต.ค. 2569: ช่วงราคานับ **รายตัวจริง** · ยกเลิกการตั้งราคาแยกไซส์ · เปิดช่วงชุดเก่าไว้ตั้งแต่แรก

### ค่าเช่าและมัดจำ

| สเปก | CosMate |
|---|---|
| `deposit_tiers` | `deposit_tiers` (ตารางเดียวกัน) · ค่าเช่าต่ำกว่า 250 = มัดจำเทียร์แรก · เกิน 2,500 = เทียร์สุดท้าย (ฟอร์มเตือนให้กำหนดมัดจำเอง) |
| `dresses` (1 ชุด = 1 ชิ้น) | ต้นทุน ราคา 3 ช่วง ล็อกราคา มัดจำกำหนดเอง อยู่ที่ `products` ใช้กับทุกไซส์ · **ช่วงราคานับแยกรายตัวจริง** (`product_items`) ตัวที่ซื้อเพิ่มทีหลังเริ่มเป็นชุดใหม่ |
| `price_phase` | ไม่เก็บ คำนวณสดด้วย `unit_phase()` จากรอบ/ค่าเช่าสะสม ทุกครั้งที่ถาม จึงไม่มีตัวนับให้เพี้ยน |
| `completed_rentals`, `total_rental_income` | นับสดจากรายการที่ออเดอร์ "เสร็จสิ้น" (`unit_completed_rentals`, `unit_rental_income` จาก Step 21) · ค่าเช่าสะสมรวมค่าวันเพิ่มด้วย |
| `price_locked` | `products.price_locked` · ตอนล็อกระบบจำช่วงของแต่ละตัวไว้ที่ `product_items.locked_phase` · ตัวที่เพิ่มหลังล็อก = ชุดใหม่ |
| `OLD_PHASE_ENABLED`, 10 รอบ | `app_settings.price_old_phase_enabled` / `price_old_after_rentals` ตั้งได้จากการ์ดราคาในฟอร์มชุด (มีผลทุกชุด) |
| `not_returned` ไม่นับรอบ | รายการที่มีการหัก "สูญหาย" (`order_deductions.type = 'lost'`) ไม่นับ (เหมือน Step 21) |
| `rental_price_snapshot`, `deposit_snapshot` | `order_items.base_rental_price` / `rental_price` / `deposit_amount` + `price_phase` ของตัวนั้นตอนจอง |
| `currentPrice(dress)` ตอนจอง | `unit_price()` ของตัวที่ระบบเลือกให้ · ระบบเลือก **ตัวที่ค่าเช่าถูกที่สุดก่อน** แล้วมัดจำ |
| ราคาที่หน้าร้าน | `product_variants.package_price` / `deposit_amount` = ราคาของตัวที่พร้อมเช่าและถูกที่สุด (ระบบอัปเดตเองเมื่อออเดอร์เสร็จสิ้น/สภาพชุดเปลี่ยน/บันทึกราคา) ก่อนเลือกวันแสดงเป็นช่วง เลือกวันแล้วแสดงราคาของตัวที่จะได้ (`quote_lines`) |
| ต้นทุนนอกช่วง / ไม่มีต้นทุน | ฟอร์มไม่เสนอราคา แอดมินกรอกเองทั้ง 3 ช่วง · ไม่มีต้นทุน = ข้ามช่วงชุดใหม่ เริ่มที่ราคาปกติ |
| ชุดที่มีอยู่ก่อน Step 25 | ทั้ง 3 ช่วง = ราคาไซส์ที่แพงที่สุดเดิม (ราคาไม่เปลี่ยน) แอดมินกด "ใช้ราคาที่แนะนำ" ในหน้าแก้ไขชุดเมื่อพร้อม |

**เพิ่มจากสเปก**

- **เช่าแยกชิ้น** — ราคาชิ้นคำนวณจากค่าเช่าเต็มชุดของตัวที่ได้ ([SQL Step 30](sql/cosmate_step30_piece_pricing.sql)) ดูหัวข้อ [ราคาเช่าแยกชิ้น](#ราคาเช่าแยกชิ้น-step-30) · มัดจำ = ตารางมัดจำตามยอดชิ้นรวม ไม่เกินมัดจำทั้งชุดของตัวนั้น (`pieces_deposit`)
- **รองเท้าที่มากับชุด** — เช่าทั้งชุดแต่ไม่รับรองเท้า หักราคารองเท้าจากค่าเช่า แต่มัดจำคิดจากค่าเช่าเต็มชุด (เหมือนข้อ 7 ราคาก่อนลด)
- **ค่าวันเพิ่ม** — ไม่มีผลกับมัดจำ มัดจำดูจากค่าเช่าวันแรกเท่านั้น

### ราคาเช่าแยกชิ้น (Step 30)

แอดมินเลือกระดับชิ้นแทนการตั้งราคา ระดับคือ หลัก 3 / รอง 2 / เสริม 1 และเลือกการเช่าแยกของแต่ละชิ้น

| การเช่าแยก | เก็บในฐานข้อมูล | ราคา |
|---|---|---|
| ระบบคำนวณตามระดับ | `rental_price` มีค่า + `price_weight` มีค่า | ตามสูตรด้านล่าง ลดตามช่วงของตัวที่ได้ |
| กำหนดราคาเอง / รองเท้าที่มากับชุด | `rental_price` มีค่า + `price_weight` ว่าง | ตายตัวทุกช่วง |
| ไม่เปิดเช่าแยก | `rental_price` ว่าง | เช่าแยกไม่ได้ แต่ระดับที่เลือกไว้ยังนับในสัดส่วน |

```
ราคาชิ้น = (ค่าเช่าเต็มชุดของตัวที่ได้ − ราคาชิ้นตายตัวทั้งหมด) × ระดับชิ้น ÷ ระดับรวมทุกชิ้น × 120%
ปัดขึ้นหลัก 10 บาท ขั้นต่ำ 100 บาท
ยอดแยกชิ้น = ผลรวมราคาชิ้นที่เลือก ไม่เกินค่าเช่าทั้งชุดของตัวนั้น
             (ไม่ได้ติ๊กรองเท้า = ไม่เกินค่าเช่าทั้งชุดแบบไม่รับรองเท้า)
```

ตัวอย่างชุดต้นทุน 1,800 บาท

| ช่วง | ทั้งชุด | เสื้อ (หลัก) | กางเกง (รอง) | วิก (เสริม) |
|---|---|---|---|---|
| ชุดใหม่ | 900 | 540 | 360 | 180 |
| ราคาปกติ | 650 | 390 | 260 | 130 |
| ชุดเก่า | 450 | 270 | 180 | 100 |

- **ค่าตั้ง:** `app_settings.piece_price_markup_percent` (120), `piece_price_min` (100), `piece_price_round` (10) เป็นค่าเริ่มต้นที่เสนอไว้ ยังรอเจ้าของร้านยืนยันจากยอดเช่าจริง
- **ตัวคูณ 120%** มีไว้ให้การเช่าทั้งชุดคุ้มกว่าการเช่าแยก ไม่ได้แก้ปัญหาชิ้นเดียวล็อกชุดทั้งตัว ปัญหานั้นคุมด้วยราคาขั้นต่ำและการเลือกเปิดเช่าแยกเฉพาะบางชิ้น
- **ชุดเดิม:** ชิ้นที่ตั้งราคาไว้ก่อน Step 30 เป็นราคาตายตัวตามเดิม จนกว่าแอดมินจะเปลี่ยนเป็นระบบคำนวณในหน้าแก้ไขชุด
- **ช่วงชุดเก่านับรอบการใช้งาน:** เช่าทั้งชุด = 1 รอบ · เช่าแยกชิ้น = ยอดชิ้น ÷ ค่าเช่าเต็มชุด ณ ตอนจอง (`order_items.round_weight`) รายการก่อน Step 30 นับ 1 รอบตามเดิม
- **จำนวนรอบที่เช่าจริง** (`unit_completed_rentals`) ยังนับเหมือนเดิม ใช้กับ `round_no` และสถิติในหน้าแก้ไขชุด
- **ค่าเช่าสะสม** ไม่เปลี่ยน ยอดเช่าแยกชิ้นเข้าค่าเช่าสะสมของตัวนั้นและนับรวมการคืนทุนอยู่แล้ว

| ไฟล์ | bucket `id-cards` แบบส่วนตัว `<user id>/id-card.jpg` (ย่อเป็น JPEG ≤ 1600px ในเบราว์เซอร์) · ลูกค้าอัปโหลด/ทับได้จนกว่าจะ verified · เปิดดูได้เฉพาะเจ้าของและแอดมิน · ลบผ่าน route ฝั่งเซิร์ฟเวอร์เท่านั้น |
| `is_blacklisted` | `profiles.trust_level = 'blacklisted'` (ของเดิม) |
| `last_rental_at` | ไม่เก็บ ใช้วันคืนของออเดอร์ที่เสร็จสิ้นล่าสุด (ยังไม่เคยเช่า = วันที่ยืนยัน) |
| "แอดมินต้องยืนยันก่อนวันรับชุด" | ออเดอร์สถานะใหม่ `awaiting_id` กันวันไว้ ยังจ่ายไม่ได้ ดูขั้นตอนด้านล่าง |
| ลบไฟล์อัตโนมัติ | `/api/cron/id-card-cleanup` (Vercel Cron ทุกวัน 02:30 น.) · ไม่ลบถ้าถูกแบนหรือมีออเดอร์ที่ยังไม่จบ |
| ลูกค้าขอลบ | ปุ่มในหน้า "บัญชีของฉัน" → `DELETE /api/id-card` (ลบไม่ได้ระหว่างมีออเดอร์ที่ยังไม่จบ) |

**ขั้นตอนการจองของลูกค้าที่ยังไม่ verified**

```
เลือกชุด/วัน → หน้าชำระเงิน: ส่งรูปบัตร (ถ้ายังไม่เคยส่ง) → create_booking → awaiting_id (กันวันไว้)
  แอดมินอนุมัติ   → pending_payment ชำระภายใน 24 ชม. + อีเมลแจ้ง → ชำระแล้ว → ตามปกติ
  แอดมินไม่อนุมัติ → cancelled ปล่อยวัน ลบรูป + อีเมลแจ้งเหตุผล → ส่งรูปใหม่แล้วจองใหม่
  ตรวจไม่ทัน       → expired (pg_cron ทุกนาที)
```

- **เส้นตายของออเดอร์** = เริ่มวันที่ร้านต้องส่งชุด (จัดส่ง: วันใช้งาน − วันขนส่ง − 1) หรือวันรับชุด (รับเอง) เวลาไทย
- เวลาตรวจบัตร = ไม่เกิน 24 ชม. หรือครึ่งหนึ่งของเวลาที่เหลือก่อนเส้นตาย (ถ้าเหลือน้อยกว่า 48 ชม.)
- เวลาชำระหลังอนุมัติ = 24 ชม. ไม่เกินเส้นตาย · เหลือไม่ถึง 30 นาทีตอนอนุมัติ = ออเดอร์หมดอายุ
- เหลือเวลาไม่ถึง 2 ชม. ตอนจอง = จองไม่ได้ (`ID_REVIEW_NO_TIME`) ให้เลือกวันไกลขึ้นหรือส่งรูปล่วงหน้า
- ลูกค้าส่งรูปไว้แล้วแต่ยังรอตรวจ (`pending`) จองต่อได้เลย · อนุมัติครั้งเดียว ออเดอร์ `awaiting_id` ทุกใบของลูกค้าคนนั้นไปรอชำระพร้อมกัน
- ออเดอร์ `awaiting_id` นับรวมกับ "ออเดอร์ค้างจ่ายสูงสุด" ของ `booking_settings`
